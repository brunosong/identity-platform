# 상품 목록과 상세

포털(:5173)에 상품을 늘어놓고, 누르면 상세로 들어가는 화면. 물건을 파는 기능이 아니라
**로그인이 필요해지는 경계를 눈에 보이게 하려고** 만들었다.

## 왜 이렇게 하나

전에는 포털에 로그인 화면과 마이페이지밖에 없었다. 그러면 "로그인한다"와 "로그인해야 한다"가
같은 말이 된다. 앱에 들어오자마자 로그인을 요구하니 경계랄 것이 없다.

| | 전 | 후 |
|---|---|---|
| 첫 화면 | 서비스 소개 카드 셋 | 상품 여덟 개 |
| 로그인 없이 볼 수 있는 것 | 소개뿐 | 상품 목록, 상품 상세 전부 |
| 로그인을 처음 요구하는 곳 | 앱에 들어오자마자 | 주문 버튼 |

상품 설명은 누구에게나 같은 값이라 신원을 물을 이유가 없다. 주문은 다르다. 누가 시켰는지를
남겨야 하므로 그때 처음 신원이 필요해진다. **그 한 칸 차이가 화면에 드러나는 것이 이 작업의
전부다.**

## 한눈에 보는 흐름

```
   /                        /products/:id
┌──────────────┐          ┌────────────────────────┐
│ 상품 8개 격자 │ ──클릭──> │ 타일 · 이름 · 가격      │
│ (로그인 무관)  │          │ 설명 · 사양            │
└──────────────┘          │                        │
                          │  로그인 O → [주문하기]   │
                          │  로그인 X → [로그인하고  │
                          │             주문하기]   │
                          └────────────────────────┘
                                       │
                            data/products.js (배열)
                            서버를 부르지 않는다
```

## 왜 그렇게 도나

**상품 데이터가 프론트에 박혀 있다.** 상품 API 가 없기 때문이다. `order-service` 는 주문만 알고
상품을 모른다. 없는 서버를 먼저 만들면 화면을 보기까지 오래 걸려서, 배열 하나로 시작했다.

대신 **화면이 그 배열을 직접 읽지 않는다.** `listProducts()` 와 `findProduct(id)` 만 부른다.
상품 API 가 생기면 고칠 자리가 그 두 함수뿐이다.

**상품 사진이 없어서 색 타일을 깐다.** 상품마다 `tone`(색상환 각도)을 하나씩 들고 있고,
그걸로 그라디언트를 만든다. 빈 회색 칸 여덟 개는 화면이 읽히지 않는다.

**주문 버튼은 아직 주문을 넣지 못한다.** 주문을 만드는 API 가 없다. 로그인 여부에 따라 버튼이
갈리는 데까지만 하고, 눌렀을 때는 그 사실을 알린다. 없는 것을 되는 척하지 않는다.

## 지키는 규칙

- **목록과 상세는 로그인을 요구하지 않는다.** `RequireAuth` 로 감싸지 않는다. 감싸는 순간 이
  화면을 만든 이유가 없어진다
- **화면은 `data/products.js` 의 배열을 직접 import 하지 않는다.** 조회 함수만 부른다
- **품절은 감추지 않고 흐리게만 한다.** 감추면 "원래 없던 상품"과 구분이 안 된다
- **가격은 `formatPrice()` 로만 찍는다.** 목록과 상세가 다른 모양으로 갈리지 않게

## 어디에 있나

| 무엇 | 파일 |
|---|---|
| 상품 배열과 조회 함수 | `frontends/portal/src/data/products.js` |
| 목록 (메인 화면) | `frontends/portal/src/pages/HomePage.jsx` |
| 상세 | `frontends/portal/src/pages/ProductDetailPage.jsx` |
| 사진 대신 쓰는 색 타일 | `frontends/portal/src/components/ProductThumb.jsx` |
| 경로 등록 | `frontends/portal/src/App.jsx` |
| 스타일 | `frontends/portal/src/styles.css` 아래쪽 |

## 아직 없는 것

- **상품 API** — 배열이 프론트에 있다. 새로고침해도 같고, 관리자가 바꿀 방법이 없다
- **주문** — `order-service` 에 주문을 만드는 API 가 없다. 조회만 있다
- **장바구니** — 주문이 없으니 담을 곳도 없다
- **로그인하고 돌아오기** — 상세 화면에서 로그인을 누르면 끝나고 마이페이지로 간다.
  보던 상품으로 돌아오지 않는다. 인가 코드 흐름은 브라우저가 앱을 떠났다 오는 길이라
  앱의 메모리가 통째로 날아가고, 어디를 보고 있었는지도 같이 날아간다.
  [인가 코드 흐름](인가-코드-흐름.md) 에 이어지는 이야기다
