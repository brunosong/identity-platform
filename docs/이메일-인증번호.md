# 이메일 인증번호

비밀번호 없이 이메일로 6자리 숫자를 받아 로그인하거나 가입하는 길.

## 왜 있나

비밀번호를 안 만들어도 되는 길이 하나 필요하다. 직원(`ADMIN` realm)은 **비밀번호 계정 자체를
갖지 않아서** 이것이 유일한 셀프 가입 수단이고, 고객은 비밀번호와 이 방식 중 고를 수 있다.

메일함을 여는 사람이 그 주소의 주인이라는 것이 전제다. 그래서 같은 장치가 두 가지 일을 한다.

```
로그인   등록된 주소에만 보낸다      "이 주소의 주인이 맞나"
가입     등록되지 않은 주소에만 보낸다  "이 주소가 정말 당신 것인가"
```

조건이 **정반대**라 경로도 따로 있다. 하나로 합치면 "이미 가입된 이메일입니다" 를 응답으로
알려주게 되고, 그것만으로 누가 가입돼 있는지 훑을 수 있다.

## 한눈에

```
  앱                         auth                        DB / 메일
   |                           |                           |
   |--- 이메일 --------------->|  최근 발송이 1분 내인가     |
   |    .../login/email-otp    |  아니면 6자리 난수 생성     |
   |    /send-code             |  해시해서 저장 ----------->| identity_email_otp
   |                           |  메일 발송 -------------->| (로컬은 로그로 대신)
   |<-- 202 (보냈든 말든) -----|                           |
   |                           |                           |
   |--- 이메일 + 코드 -------->|  최신 미사용 챌린지 조회    |
   |    .../login/email-otp    |  차단·만료·해시 비교        |
   |                           |  쓴 것으로 표시            |
   |<-- access / refresh ------|  토큰 발급                 |
```

## 응답이 늘 같다

발송 요청은 **보냈든 안 보냈든 202** 다. 쿨다운에 걸려도, 등록되지 않은 주소여도(로그인용),
이미 가입된 주소여도(가입용) 같은 응답이다.

무엇을 숨기는지가 분명하다. **그 주소가 우리 서비스에 등록돼 있는지**다. 다르게 답하면 주소를
넣어보는 것만으로 가입자 명단을 만들 수 있다.

## 코드를 지키는 네 가지

```
수명       5분
시도       5회 틀리면 그 챌린지는 죽는다. 새로 받아야 한다
재발송     같은 주소로 60초 안에 다시 보내지 않는다
저장       해시로 저장한다. 원문은 메일에만 있다
```

**해시로 저장하는 것**이 눈에 띄는 선택이다. 6자리 숫자를 해시해 봐야 백만 가지라 마음먹으면
뒤집을 수 있다. 그래도 그렇게 두는 이유는, DB 를 들여다본 사람이 **그 자리에서 바로** 로그인하지는
못하게 하려는 것이다. 5분이라는 수명이 그 계산 시간과 맞물린다.

**시도 횟수는 독립 트랜잭션에서 올린다.** 틀리면 예외로 끝나고 그 예외가 트랜잭션을 되돌리는데,
시도 횟수까지 되돌아가면 5회 제한이 영원히 걸리지 않는다. 비밀번호 잠금과 같은 처방이다.

## 로컬에서는 메일이 안 나간다

`local` 프로파일에서는 코드가 `123456` 으로 고정되고 발송 대신 로그에 찍힌다. 메일 서버 없이
흐름 전체를 돌려보기 위한 것이고, 다른 프로파일에서는 그 자리가 없다.

## 지키는 규칙

- **보낼지 말지는 부르는 쪽이 판단한다.** 발급기는 "여기 오면 보낸다" 만 한다
- **한 이메일에 살아 있는 챌린지는 최신 하나.** 검증은 늘 최신 미사용 건을 본다
- **쓴 코드는 쓴 것으로 표시한다.** 같은 코드로 두 번 들어오지 못한다
- **챌린지에 용도 표시가 없다.** 로그인용과 가입용의 조건이 서로 배타적이라(등록됨 / 등록 안 됨)
  한 주소가 동시에 양쪽 대상이 될 수 없다. 용도가 더 늘면 그때 구분을 넣는다

## 어디에 있나

| 무엇 | 어디 |
|---|---|
| 로그인 경로 | `auth-web/.../web/client/identity/EmailOtpLoginApiController.java` |
| 가입 경로 | `auth-web/.../web/client/identity/AuthSelfRegistrationApiController.java` |
| 발급(쿨다운, TTL, 로컬 고정코드) | `auth-application/.../identity/service/EmailOtpIssuer.java` |
| 검증(만료, 시도 제한) | `auth-application/.../identity/service/EmailOtpVerifier.java` |
| 챌린지 규칙 | `auth-domain/.../domain/identity/EmailOtpChallenge.java` |
| 표 | `identity_email_otp` (V1) |

## 아직 없는 것

- **만료된 챌린지 치우기.** 쓰이지 않은 행이 그대로 남는다
- **발송 실패 처리.** 메일이 나가지 않아도 사용자는 202 를 받는다. 보냈다는 기록과 실제 발송
  결과가 갈리는 자리다
- **주소당 하루 발송 한도.** 60초 쿨다운만 있어서, 하루 종일 1분 간격으로 보내는 것은 막지 못한다
- **code 흐름과의 연결.** 로그인 화면(`/realms/{realm}/auth`)에는 아직 이 방식이 없다.
  비밀번호 칸만 있다
