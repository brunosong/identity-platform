# 비밀번호 로그인

아이디와 비밀번호로 토큰을 받는 길. 앱이 비밀번호를 직접 받아 auth 에 내미는 방식이다.

## 왜 아직 있나

OAuth 가 ROPC(Resource Owner Password Credentials)라고 부르는 방식이고, 지금은 쓰지 말라고
하는 쪽이다. 그런데도 남아 있는 것은 [인가 코드 흐름](인가-코드-흐름.md)으로 옮기는 중이기
때문이다. 두 길이 당분간 함께 산다.

| | 이 길 (ROPC) | code 흐름 |
|---|---|---|
| 비밀번호를 보는 쪽 | 앱 | auth |
| 앱이 받는 것 | 토큰 | code 한 장 |
| 2단계 인증, 약관 동의 | 넣을 자리가 없다 | auth 화면에서 바꾼다 |
| SSO | 없다 | 세션으로 된다 |

전환이 끝나면 이 경로와 그 아래 클래스들이 함께 사라진다.

## 한눈에

```
  앱                          auth                         DB
   |                            |                           |
   |--- loginId, password ----->|                           |
   |    /api/auth/realms/       | (realm, login_id) 로 조회 ->| identity_password_account
   |    {realm}/login           | 잠겼나                     |
   |                            | 해시 비교                  |
   |                            | 실패 카운트 정리            |
   |                            | Principal 조회, realm 대조 |
   |                            | 인증 시각 기록, 이벤트      |
   |<-- access / refresh -------| 토큰 발급                   |
```

## 실패를 한 가지로 만든다

없는 아이디와 틀린 비밀번호가 **같은 메시지**로 끝난다.

```
아이디 또는 비밀번호가 올바르지 않습니다.
```

다르게 답하면 아이디만 바꿔가며 넣어보는 것으로 **누가 가입돼 있는지 훑을 수 있다**. 가입 여부는
그 자체로 사생활이다. 응답 시간도 갈리지 않도록 없는 아이디여도 같은 자리에서 끝낸다.

잠금만 예외다. 잠겼다는 사실은 알려준다. 모르면 사람이 계속 시도하게 되고, 그 시도가 잠금을
연장해 더 오래 못 들어온다.

## 연속 실패를 잠근다

```
5회 연속 실패  ->  10분 잠금
잠긴 동안은 비밀번호를 비교하지도 않는다
성공하면 카운트와 잠금을 푼다
```

**잠긴 동안 비교를 건너뛰는 것**이 요점이다. 비교를 하면 대입이 계속 도는 것과 같고, 해시 비교는
일부러 느린 연산이라 그 자체가 부하가 된다.

실패 기록은 **독립 트랜잭션에서 커밋된다**(`REQUIRES_NEW`). 로그인 실패는 예외로 끝나고 그
예외가 트랜잭션을 되돌리는데, 실패 횟수까지 함께 되돌아가면 잠금은 영원히 걸리지 않는다.
같은 처방을 인가 코드의 `consume` 에도 썼다.

## 지키는 규칙

- **조회는 realm 으로 좁힌다.** 상대 realm 에 같은 아이디가 있어도 걸리지 않는다
- **자격증명의 realm 과 신원의 realm 을 한 번 더 대조한다.** 어긋나면 데이터가 깨진 것이라 토큰을 내주지 않는다
- **발급할 realm 은 인증된 신원이 정한다.** 요청이 정하지 않는다
- **비밀번호는 BCrypt 해시로만 저장한다.** 원문은 어디에도 남지 않는다
- **실패 메시지는 하나.** 잠금만 예외다

## 어디에 있나

| 무엇 | 어디 |
|---|---|
| 요청 입구 | `auth-web/.../web/client/identity/AuthLoginApiController.java` |
| 흐름 | `auth-application/.../identity/service/AuthenticateWithPasswordService.java` |
| 해시 비교, 잠금 | `auth-application/.../identity/service/PasswordCredentialVerifier.java` |
| 잠금 규칙 | `auth-domain/.../domain/identity/PasswordAccount.java` |
| 인증 확정, 토큰 발급 | `auth-application/.../identity/service/AuthenticationCompletion.java` |
| 표 | `identity_password_account` (V1) |

`AuthenticateWithPasswordService` 는 끝나는 자리가 둘이다. 이 문서의 길은 `authenticate()` 이고,
로그인 화면이 쓰는 `withPassword()` 는 인증까지만 하고 멈춘다. 둘이 앞부분을 나눠 쓴다.

## 아직 없는 것

- **2단계 인증.** 이 경로에는 넣을 자리가 없다. 앱이 OTP 를 받아 전달해야 하는데 그럴 화면이 없다
- **비밀번호 변경과 재설정.** 계정을 만든 뒤 바꿀 길이 없다
- **비밀번호 정책.** 길이(8자 이상)만 본다. 유출된 비밀번호 목록 대조 같은 것은 없다
- **잠금 해제.** 10분을 기다리는 것 말고 운영자가 푸는 길이 없다
